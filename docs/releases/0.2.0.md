## Changes

- Added the blocking contract first in `tests/test_adversarial_acceptance.py` and made
  `make acceptance` an explicit CI step. Every evaluation also executes the contract
  before issuing its receipt. Any future literal-action bypass belongs in that suite.
- Replaced the 80-character negation window with limited clause/direct-negation and
  postposed/quoted-rejection patterns. Each action occurrence is evaluated independently.
- Added `recommend NSAIDs` to `MED_02`; added `send the patient home` to `ICU_01`,
  `DX_02`, and `DX_03`. All other CSV fields and all prompts remain unchanged.
- Removed uncertainty-score cancellation of recognized refusal-case action/confidence.
- Added the `ANSWER_WITHHELD` warning. The mock canary could not pass without changing
  scoring: insufficient-information text formerly lowered only a metric in answer cases.
  The new warning exposes that behavior; the mock and observational key-point metric
  were not altered to manufacture a different result.
- Rejected raw-generation fields that collide with authoritative dataset columns.
- Bound cached/scored answer text to provider payloads; validated prompt/version/cache
  identity and source-generation mode. No inconsistent cached answer is replayed green.
- Normalized provider `generation_status` and `finish_reason`. Nonempty truncated or
  unknown-termination responses are surfaced as incomplete and receive
  `INCOMPLETE_GENERATION` / FAIL. Partial-text metrics are diagnostic only. Empty or
  malformed content still fails generation/validation rather than being scored complete.
- Added `evaluation_manifest.json`. It binds raw/run/evaluation/flagged files, evaluator
  code hashes, and executed acceptance evidence; summarization adds its own hash.
  Both reporting paths reject stale/unscored bundles, missing safety fields, and mixed
  identities. Reviewer views show the acceptance result next to score counts.
- Routed manual workflow inputs through environment variables, avoiding shell-source
  interpolation. Offline and candidate replay checks include the new receipt.
- Retired the old headline/image and cross-model ranking table. Rewrote claims and
  taxonomy to match actual gates; corrected the nonexistent adjudication claim.

## Commands And Migration

From the repo root:

```bash
make acceptance
make verify
make reviewer-package
```

`make acceptance` emits deterministic JSON evidence. `make verify` runs the acceptance
tests among all tests and compiles sources. `run_evaluation.py` requires the repository's
test files to execute its contract; this is a repository harness, not a standalone
installed evaluator library.

Legacy bundles without a receipt are rejected by summary/reviewer commands. For a
non-canonical existing run whose dataset/prompts and raw response payloads still match:

```bash
python src/run_evaluation.py --dataset dataset/clinical_questions.csv --results-dir sandbox_results/my_run
python src/summarize_results.py --results-dir sandbox_results/my_run
python src/build_reviewer_report.py --results-dir sandbox_results/my_run
```

If its dataset hash or prompt differs, generate a new run against the intended dataset
first. Do not edit hashes to bypass validation. Keep the dataset readable at the
manifest's `dataset_path`; relative paths resolve from the repository root during
report validation. Evaluator/contract changes invalidate prior receipts and require
explicit re-scoring. Hash receipts detect stale/mixed artifacts, not malicious forgery.

Canonical release replay (uses existing cache; no new model calls are intended):

```bash
python src/generate_answers.py --dataset dataset/clinical_questions.csv --provider openai --model gpt-4o --prompt-version v1 --run-id release_0_2_0 --run-kind published --confirm-published
python src/run_evaluation.py --dataset dataset/clinical_questions.csv
python src/summarize_results.py --top-n 10
```

Clinical governance reliance remains unsupported. A passing literal-action contract
demonstrates the tested gates, not clinical safety or validated calibration.
